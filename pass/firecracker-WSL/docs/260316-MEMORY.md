## 2026-03-16 Session Memory：OpenCode + Firecracker VM 平台

- **目標與假設**
  - 每個 user 一台 Firecracker microVM。
  - OpenCode 以 **API Server** 形式提供服務：`opencode serve --port 4096`，使用者不直接 SSH 進 VM。
  - skills 分為：
    - 平台共用 RO skills：`~/.config/opencode/skills`。
    - 專案 / 私有 skills：各專案目錄下的 `project/skills`。
  - 每個 user 有獨立、持久化的 workspace（但 VM 本身可回收，一律回收策略）。

- **Base rootfs 策略**
  - 放棄早期 bionic 精簡 rootfs + 就地安裝模式（apt/dpkg 不完整、glibc 相容性問題）。
  - 改用 Ubuntu 24.04 (noble) 官方 cloud rootfs（`noble-server-cloudimg-amd64-root.tar.xz`）作為基礎，確保：
    - 完整 apt/dpkg。
    - 可安裝 JS/Python toolchain + build-essential。
  - 新增腳本 `scripts/prepare-ubuntu-noble-rootfs.sh`：
    - 下載 root tarball → 建立 ext4 容器 → 解壓。
    - chroot 進去安裝：`curl`, `ca-certificates`, `git`, `python3+pip+venv`, `nodejs+npm`, `build-essential`。
    - 使用官方腳本安裝 OpenCode：`curl -fsSL https://opencode.ai/install | bash`。
    - 建立 skills skeleton：`/etc/skel/.config/opencode/skills` 與 `/root/.config/opencode/skills`。
    - 建立 `systemd` 服務 `opencode-serve.service`，開機自動跑 `opencode serve --port 4096 --hostname 0.0.0.0`（官方為 `--hostname`，勿用 `--host`）。
  - 舊腳本 `scripts/build-base-rootfs-opencode.sh` 已改為 **wrapper**：
    - 單純呼叫 `prepare-ubuntu-noble-rootfs.sh` 產生 `bin/ubuntu-noble-base.rootfs.ext4`（預設 12GB，可調整）。

- **VM 啟動與啟動時間量測**
  - 新增腳本 `scripts/run-noble-vm-with-opencode.sh`：
    - 參數：`--kernel <vmlinux>`、`--rootfs <ubuntu-noble-base.rootfs.ext4>`、`--vm-id`。
    - 建立 tap（預設 `fc-<vm-id>`）、host IP `172.30.0.1/24`，預期 guest IP `172.30.0.2`（需要與 VM 內 netplan/cloud-init 對齊）。
    - 啟動 Firecracker，設定 kernel / rootfs / network interface，呼叫 `InstanceStart`。
    - 記錄 `START_TS`（ms），之後由 host 持續對 `http://<VM_IP>:4096/` 用 `curl` 探測：
      - 第一個成功回應時間為 `READY_TS`。
      - 啟動時間（ms） = `READY_TS - START_TS`。
    - 將結果寫入 `logs/opencode-startup-<vm-id>-YYYYMMDD-HHMMSS.json`，包含 `startup_ms` 等欄位，方便之後重複比較不同設定下的啟動時間。
