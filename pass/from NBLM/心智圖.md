- AI Agent 運行環境與 Sandboxing 技術
  - 核心問題與挑戰
    - 沙箱問題 (Sandboxing Problem)
    - 隔離與效能的矛盾
    - 安全邊界與多租戶隔離
    - 生產環境部署率低 (僅 5%)
      - 硬體級 KVM 隔離
    - Firecracker MicroVM
      - 極簡設計 (Virtio)
      - 啟動速度快 (約 125-150ms)
      - 低記憶體開銷
  - 隔離技術 (Isolation Technologies)
    - gVisor
      - 應用程式核心攔截
      - 效能開銷約 10-20%
    - Docker 容器
      - 共享宿主機核心
      - 安全性較低 (易逃逸)
  - 存儲與持久化架構
    - 底層存儲
      - MinIO (S3 兼容物件存儲)
      - JuiceFS (分散式文件系統)
    - 掛載策略
      - Base Rootfs (唯讀系統)
      - Shared Skills (唯讀映像)
    - Nextcloud (磁碟空間管理入口)
      - User Workspace (持久化可寫)
  - 安全威脅與防範
    - Prompt Injection (提示注入)
    - 遠端代碼執行 (RCE)
    - 資源耗盡 (Resource Exhaustion)
    - Jailer 屏障 (沙盒加固)
      - E2B (Firecracker 基礎)
  - 平台與標準化
    - Sandboxing 平台
      - Modal (gVisor 基礎)
    - Model Context Protocol (MCP) 標準化
      - Daytona (開源自託管)
  - 效能優化策略
    - Warm Pool (預熱池)
    - Snapshot & Restore (快照恢復)
    - Sparse Files (稀疏文件技術)
